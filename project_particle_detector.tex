\subsection{Detectors}

\subsubsection{SubDetector}

With the detectors, my initial plan is to have a pure abstract base class \texttt{SubDetector} from which \texttt{Tracker}, \texttt{Calorimeter} and \texttt{MuonChamber} etc can be derived.
Then have a the generic overall detector \texttt{DetectorSystem} that stores the \texttt{SubDetector}s in a vector like.

Should \texttt{SubDetector} change the Particle in anyway, what if the detection changes the energy due to a collision, something to consider.

I don't believe any need for specific copy/move constructors/assignment operators as the data members are only \texttt{std::string} and \texttt{bool}.

Considering how to control if a \texttt{SubDetector} detects a \texttt{Particle} passed through it.
My two current ideas are using a \texttt{Particle} distinct data member that is a vector with strings, referring to which \texttt{SubDetectors} can detect this \texttt{Particle}. Then in the derived \texttt{SubDetector} member function \texttt{detect} it would use an if statement distinguishing if the \texttt{Particle} passed through can be detected.

The other method I was considering was using a polymorphic virtual \texttt{Particle} member function, for example \texttt{interacts\_with\_calorimeter}, which will return a bool depending on if that derived \texttt{Particle} interacts with that detector.
Then in the derived \texttt{SubDetector} member function \texttt{detect}, \texttt{particle.interacts\_with\_calorimeter} can be called which will just return true or false.

I find this method cleaner as no loop through a vector of strings or enums is needed in the \texttt{detect}. It also allows for flexibility, in the sense perhaps \texttt{Electron} only interacts with \texttt{Calorimeter} when it has certain energies.

Noted that \texttt{detect} for all \texttt{SubDetector} should first have their \texttt{status} checked as if it is off then nothing should be detected.
As this is common to all \texttt{SubDetector} I initially thought to make it within the base \texttt{detect}. However, calling this function within the derived \texttt{detect} could not leave the derived function using \texttt{return} and stop the detection process. But I still did not like doing this for each derived class
\begin{lstlisting}[
    style=vscode, 
    caption={Example of repetition for status check in derived SubDetectors},
    label={lst:repetition_status}
]
if (!status)
{
    std::cout << "Calorimeter (" << sd_name << ") is off, no detection." << std::endl;
    std::cout << std::endl; // Line break.
    return; // Exit function.
}
\end{lstlisting}
My solution was to make a base member function \texttt{is\_off}, as seen in Code snippet \ref{lst:repetition_status}, which prints the information required (the same for all \texttt{SubDetector}) and returns true if off and false if on.
\begin{lstlisting}[
    style=vscode, 
    caption={Base function to check status, called in derived class detect.},
    label={lst:is_off}
    ]
bool SubDetector::is_off() const
{
    if (!status)
    {
        std::cout << "SubDetector (" << sd_name << ") is off. No detection." << std::endl;
        std::cout << std::endl; // Line break.
        return true;
    }
    else
    {
        return false;
    }
}
\end{lstlisting}
This is then used in the derived \texttt{detect} function, being used to exit the function prior to detection. 


Also detect should not necessarily keep \texttt{Particle} constant as the detection may change some of the kinematics something to note??

\subsubsection{DetectorSystem}

Now will create the class that can store multiple \texttt{SubDetector} classes to match the likes of \textcolor{red}{ATLAS or CMS} and print the overall configuration. This will be a container class.
My plan is to use pointers and vectors to control ownership of the multiple \texttt{SubDetector} classe, via having the data member shown in Code snippet \ref{lst:container_pointer}.
\begin{lstlisting}[
    style=vscode, 
    caption={Data member for \texttt{DetectorSystem} to manage the ownership of multiple \texttt{SubDetector} classes},
    label={lst:container_pointer}
    ]
    private:
    std::vector<std::unique_ptr<SubDetector>> sub_detectors;
\end{lstlisting}
