\section{Design process \& considerations}

My initial consideration is that I will need to change my particle base class from assignment 5.
In assignment 5 the lepton was required to be the base class, however now I need to move that responsibility to the Particle class.
Assignment 5 also has a lepton hierarchy already built in, however initially my plan is to make the Particle class the pure base class with one simple derived class which can be pushed through my SubDetectors which will be my main focus in the beginning, so to keep things simple and clean.

I also note that I may want better error and exit logic.

\subsection{Detectors}

With the detectors, my initial plan is to have a pure abstract base class \texttt{SubDetector} from which \texttt{Tracker}, \texttt{Calorimeter} and \texttt{MuonChamber} etc can be derived.

Then have a the generic overall detector \texttt{DetectorSystem} that stores the \texttt{SubDetector}s in a vector like.

Should \texttt{SubDetector} change the Particle in anyway, what if the detection changes the energy due to a collision, something to consider.

I don't believe any need for specific copy/move constructors/assignment operators as the data members are only \texttt{std::string} and \texttt{bool}.
